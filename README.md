# Практика 1. Сокращатель ссылок

Сервис принимает длинную ссылку, выдаёт короткий код и по этому коду перенаправляет
обратно. Хранение — в памяти, без базы данных. Всего два маршрута.

## Зачем эта практика

Это **разминка**: знакомство с языком, инструментами и рабочим окружением.

За две недели нужно освоиться с четырьмя вещами:

- **язык** — структуры, методы, интерфейсы, синхронизация доступа к общим данным;
- **инструменты** — `go test`, детектор гонок, линтер, `make`;
- **окружение** — сборка образа, `docker compose`, пайплайн;
- **привычка оставлять следы** — структурированные логи, по которым видно, что происходило.

## С чего начать, если Go незнаком

Курс не про язык, но и не мимо него. Один вечер на Go потратить нужно.

1. Пройти [A Tour of Go](https://go.dev/tour/) — разделы «Basics», «Methods and interfaces»
   и «Concurrency»: в последнем разбирается `sync.Mutex`, без которого хранилище не написать.
   «Generics» в этой практике не понадобятся.
2. Из стандартной библиотеки понадобятся `net/http`, `encoding/json`, `net/url`, `log/slog`,
   `os`, `strconv`, `errors`, `sync`, `math/rand/v2`, `time`. Зависимостей от сторонних
   пакетов в этой практике нет.

**О чём из языка могут быть вопросы на защите.** О том, что влияет на поведение программы:

- что такое `map`, как она устроена и что произойдёт при параллельной записи без синхронизации;
- что такое интерфейс и как тип его реализует — где об этом написано и когда компилятор
  обнаружит несоответствие;
- чем срез отличается от массива и что делает `append` при нехватке ёмкости;
- что делает `defer` и в каком порядке выполняются отложенные вызовы;
- чем получатель по значению отличается от получателя по указателю.

Вопросов о том, что ищется за пять секунд и ни на что не влияет, не будет: порядок
аргументов у функций форматирования, точные имена пакетов, тонкости объявлений.

## Как развернуть каркас

Рядом с этим файлом лежит `lab-init.sh`. Скачайте его и запустите в корне
своего репозитория:

```bash
bash lab-init.sh
```

Скрипт создаст подкаталог `lab01/` с файлами каркаса. Разворачивается каркас только
в пустой каталог — если `lab01/` уже существует и не пуст, скрипт откажется работать,
чтобы не затереть написанное.

Дальше:

```bash
cd lab01
make test    # тесты падают, пока не написано хранилище
make up      # поднять сервис
```

Сразу после развёртывания каркас не проходит тесты: `go test ./...` падает
с `storage.New: не реализовано`. Так и задумано.

**Почему часть файлов менять нельзя.** Одна из проверок — тест, который приходит
из пайплайна курса и в репозитории решения не лежит. Перед прогоном он копируется
в дерево модуля и собирается вместе со сданным кодом. Если переименовать пакет,
конструктор или изменить сигнатуры, тест не соберётся.

## Что нужно сделать

Порядок необязательный, но удобный: хранилище стоит сделать первым — его можно
полностью проверить тестами, не поднимая сервис.

### 1. Хранилище

Реализовать `storage.New()` — хранилище в памяти, реализующее уже объявленный интерфейс:

```go
// ErrCodeTaken возвращается, если код уже занят другой ссылкой.
var ErrCodeTaken = errors.New("code already taken")

type Storage interface {
    // Save сохраняет ссылку под кодом.
    // Проверить, что код свободен, и записать нужно одной неделимой операцией.
    Save(code, url string) error

    // Lookup возвращает ссылку по коду.
    Lookup(code string) (url string, ok bool)
}

func New() Storage
```

Ключевое требование: **проверить, что код свободен, и записать ссылку нужно одной
неделимой операцией.** `Save` возвращает `ErrCodeTaken`, если код уже занят, и никогда
не перезаписывает сохранённое значение.

`net/http` обрабатывает каждый запрос в отдельной горутине, поэтому доступ к хранилищу
всегда конкурентный. Если развести проверку и запись — сделать `Lookup`, а потом `Save`, —
два разных адреса могут получить один код, и один из них потеряется: тихо, без ошибки
и без падения.

Дописать недостающие тесты в `storage_test.go`. Три имеющихся проверяют работу в один
поток; не хватает того, ради чего практика и затевалась: несколько горутин одновременно
сохраняют один и тот же код, успешной должна оказаться ровно одна запись, а `Lookup`
после этого возвращает адрес победителя. На защите может быть вопрос, что проверяет
каждый из тестов.

### 2. Конфигурация

Только переменные окружения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HTTP_ADDR` | `:8080` | адрес прослушивания |
| `BASE_URL` | `http://localhost:8080` | префикс для `short_url`; абсолютный адрес со схемой и хостом |
| `CODE_LENGTH` | `7` | длина кода, целое ≥ 1 |
| `LOG_LEVEL` | `info` | уровень логирования: `debug`, `info`, `warn` или `error` |

Если значение не разбирается или не соответствует описанному в таблице, сервис **не должен
стартовать**: он завершается ненулевым кодом и сообщает, какая переменная не прошла
проверку. Сервис, поднявшийся с некорректной конфигурацией, ломается позже
и в менее очевидном месте.

### 3. HTTP

Два маршрута на `net/http.ServeMux` из стандартной библиотеки. Тела — JSON, кодировка UTF-8.

| Метод и путь | Назначение |
|---|---|
| `POST /links` | создать короткую ссылку |
| `GET /r/{code}` | перенаправить на исходную |

#### `POST /links`

```
POST /links
Content-Type: application/json

{"url": "https://example.com/very/long/path"}
```

```
201 Created
Content-Type: application/json

{"code": "aB3xK9z", "short_url": "http://localhost:8080/r/aB3xK9z"}
```

`short_url` собирается из `BASE_URL`, префикса `/r/` и кода. Завершающий слеш
в `BASE_URL` отбрасывается: `http://localhost:8080/` и `http://localhost:8080`
дают одинаковый `short_url`.

| Код | Когда |
|---|---|
| 201 | ссылка создана |
| 400 | тело не разбирается, `url` пуст, не абсолютный или схема не `http`/`https` |
| 405 | метод не `POST` — `ServeMux` отвечает сам и ставит заголовок `Allow` |
| 500 | не удалось подобрать свободный код за отведённое число попыток |

#### `GET /r/{code}`

```
302 Found
Location: https://example.com/very/long/path
```

| Код | Когда |
|---|---|
| 302 | код найден |
| 404 | код не найден |
| 405 | метод не `GET` и не `HEAD` — `ServeMux` отвечает сам и ставит заголовок `Allow` |

#### Короткий код

- **Алфавит:** `0-9 A-Z a-z`, 62 символа.
- **Длина:** из конфигурации, по умолчанию 7.
- **Генерация случайная.**

Сервис генерирует код и пытается сохранить ссылку. Если код уже занят, генерирует новый —
до пяти попыток, затем отвечает 500. Занят код или нет, решает хранилище: оно возвращает
`ErrCodeTaken`.

#### Ошибки

Единый формат тела: `{"error": "краткое описание"}`.

### 4. Логи

Структурированные, JSON, одна строка на событие. Инструмент — `log/slog`.

На каждый запрос **ровно одна** запись с полями:

| Поле | Значение |
|---|---|
| `method` | метод |
| `path` | путь |
| `status` | код ответа |
| `duration_ms` | длительность обработки |

Запись о запросе идёт на уровне `info`: при `LOG_LEVEL=error` таких записей
в выводе быть не должно.

## Как проверять локально

```
make test      # тесты
make race      # тесты под детектором гонок
make lint      # линтер
make up        # docker compose up --build -d
make down      # остановить
```

Проверить контракт вручную после `make up`:

```
curl -s -X POST localhost:8080/links -H 'Content-Type: application/json' \
     -d '{"url":"https://example.com/very/long/path"}'
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' localhost:8080/r/КОД
```
